Deployment

Recommended path: Vercel for the static frontend, Render for the warm-process backend, Supabase for Postgres. This page is a navigable summary; the authoritative step-by-step lives in FREE_HOSTING_GUIDE.md at the repo root — read that alongside render.yaml if you're actually deploying.

1. Supabase Postgres

Create a project, then use the Transaction Pooler endpoint (port 6543, IPv4) — not the session pooler:

DATABASE_URL=postgresql+psycopg://USER:ENCODED_PASSWORD@aws-0-REGION.pooler.supabase.com:6543/postgres?sslmode=require

URL-encode special characters in the password (? / + & @ :).

2. Backend on Render recommended

  1. Push the repo to GitHub, then in Render choose New → Blueprint and point it at this repo. Render reads the root render.yaml and proposes the macquiz-backend free web service (rootDir: backend).
  2. Before first deploy, set region in render.yaml to whatever Render region is closest to your actual Supabase project region — this is Lever 2's cross-region latency fix, and oregon in the committed file is a placeholder since no real Supabase region exists in this repo.
  3. Fill in every env var marked sync: false in render.yaml: DATABASE_URL, CORS_ORIGINS, ADMIN_EMAIL, ADMIN_PASSWORD, GEMINI_API_KEY. SECRET_KEY is auto-generated for you.
  4. Deploy, then run the one-time bootstrap once, from your machine, against the production DATABASE_URL — the app deliberately does not do this on boot: 
    cd backend
DATABASE_URL="..." ADMIN_EMAIL="..." ADMIN_PASSWORD="..." python -m app.bootstrap
    Safe to re-run (idempotent) after adding new model columns.
  5. Verify: /health reports "database": "connected", /docs loads, login works.

Render's free web services spin down after 15 minutes idle and cold-restart on the next request — that only replays the (now DB-free) process boot, not the one-time bootstrap step.

2b. Alternative: backend on Vercel too not recommended

backend/vercel.json still exists for this path. Same env vars as above, plus a manually-chosen SECRET_KEY (Render generates one; Vercel doesn't) and an explicit "regions": ["<region>"] key added to backend/vercel.json yourself, since Vercel has no dashboard field for it like Render does. You give up Lever 1's warm-process win on this path — it exists only for teams that don't want a second host to manage.

AI endpoints on this path: the backend already self-bounds Gemini calls at 25s/20s with a rule-based fallback, so the real risk is Vercel's function duration limit killing the request before that internal timeout fires. Verify your project's actual Function Max Duration in the Vercel dashboard exceeds ~30s before relying on this path for AI features — see Fix Status item 4.

3. Frontend on Vercel

frontend/vercel.json is already configured (SPA rewrite to index.html). Set root directory to frontend, then set:

VITE_API_BASE_URL=https://your-backend-domain.onrender.com

4. Close the CORS loop

Once the frontend's final Vercel URL exists, update the backend's CORS_ORIGINS to include it and redeploy the backend.

5. First-login checklist

  • Log in with the admin credentials you set.
  • Create one teacher and one student.
  • Create a test quiz and submit one attempt.
  • Confirm data persists after a redeploy.
