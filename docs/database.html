Database Schema

10 tables, defined in backend/app/models/models.py (SQLAlchemy ORM). Works against SQLite (local dev) or Postgres (Supabase, production) — column lengths are chosen for MySQL compatibility too, though MySQL isn't the primary target.

users ──┬── created quizzes (quizzes.creator_id)
        ├── created subjects (subjects.creator_id)
        ├── created question_bank rows (question_bank.creator_id)
        ├── quiz_attempts (as student)
        └── quiz_assignments (as assigned student)

subjects ── quizzes (subject_id, nullable) ── questions (quiz_id)
                                            └── question_bank (subject_id) ── questions (question_bank_id, optional link)

quizzes ── quiz_attempts (quiz_id) ── answers (attempt_id, question_id)
        └── quiz_assignments (quiz_id)

revoked_tokens / user_token_blocks ── standalone session-management tables (no FK to a specific token, keyed by jti / user_id)

Core tables

users

identity + role for admin / teacher / student
ColumnTypeNotes
idIntegerPK
emailString(255)unique indexed
hashed_passwordString(255)
first_name, last_nameString(100)
roleString(50)'admin' | 'teacher' | 'student'
is_activeBooleandefault true
created_at, last_activeDateTimedefault datetime.utcnow
student_idString(100)unique indexed, nullable (students only)
department, class_year, phone_number, profile_imageString / Textnullable, student-facing fields

quizzes

scheduling, live sessions, marking scheme
ColumnTypeNotes
idIntegerPK
title, descriptionString(500) / Text
creator_idIntegerFK → users.id
subject_idIntegerFK → subjects.id nullable
department, class_yearStringnullable, target audience filter
scheduled_at, duration_minutes, grace_period_minutesDateTime / Integergrace period defaults to 5 min
is_live_session, live_start_time, live_end_timeBoolean / DateTimelive proctored session fields
total_marks, marks_per_correct, negative_markingFloatmarking scheme
is_activeBooleandefault false
created_at, updated_atDateTimeutcnow default + onupdate

questions

quiz-owned question instances
ColumnTypeNotes
idIntegerPK
quiz_idIntegerFK → quizzes.id
question_bank_idIntegerFK → question_bank.id nullable, set if pulled from bank
question_text, question_typeText / String(50)'mcq' | 'true_false' | 'short_answer'
option_a..d, correct_answerString(500)
marks, orderFloat / Integerquestion order within the quiz

quiz_attempts

one row per student attempt
ColumnTypeNotes
idIntegerPK
quiz_idIntegerFK → quizzes.id
student_idIntegerFK → users.id
score, total_marks, percentageFloat
started_atDateTimedefault utcnow — timer/grace-period comparisons rely on this being UTC
submitted_at, time_taken_minutesDateTime / Floatnullable until submitted
is_completed, is_gradedBoolean

answers

per-question response within an attempt
ColumnTypeNotes
idIntegerPK
attempt_idIntegerFK → quiz_attempts.id
question_idIntegerFK → questions.id
answer_text, is_correct, marks_awardedText / Boolean / Float
UNIQUE(attempt_id, question_id) as uq_answers_attempt_question — INDEX(attempt_id, question_id) as ix_answers_attempt_question

This composite index is what lets the all-attempts/my-attempts endpoints batch-load answers via IN (...) instead of one query per attempt.

Session management (JWT revocation)

revoked_tokens

single-token logout
ColumnTypeNotes
idIntegerPK
jtiString(64)unique indexed
subjectString(255)usually the user's email, indexed
revoked_at, expires_atDateTimeexpires_at lets old rows be pruned

user_token_blocks

global logout-everywhere marker
ColumnTypeNotes
idIntegerPK
user_idIntegerFK → users.id unique indexed
revoked_beforeDateTimeany JWT with an earlier iat is rejected
All timestamp columns default to datetime.utcnow (standardized repo-wide) so they compare correctly against the UTC-based quiz timer/grace-period logic. See Architecture for the auth/revocation flow these last two tables support.
