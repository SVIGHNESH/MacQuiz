# Free Hosting Guide (MacQuiz)

This guide gives you a **fully free deployment** using:
- **Frontend**: Vercel (free)
- **Backend (FastAPI)**: Render (free web service) - recommended
- **Database**: Supabase Postgres (free tier)

Render's free web service holds one always-warm process, so the backend gets a real pooled `SQLAlchemy` connection pool and pays no per-request cold start.
That eliminates the biggest latency source of this app's actual peak (many students hitting `POST /attempts/start` at the same second for a live quiz).
See `render.yaml` at the repo root for the ready-to-use Render Blueprint.

If you'd rather keep everything on Vercel, section 2b below covers that path instead - it still applies the region-pin and `prepare_threshold=None` fixes, but a serverless backend cannot hold a warm pool or a warm process the way Render can.

> Note: Free-tier limits can change over time. If any plan changes, keep the same architecture and swap to another free host/Postgres provider.

## 1) Create free Postgres database (Supabase)

1. Create a new project in Supabase.
2. Open **Project Settings → Database**.
3. Copy your connection string and use this SQLAlchemy format:

```env
DATABASE_URL=postgresql+psycopg://USER:ENCODED_PASSWORD@aws-0-REGION.pooler.supabase.com:6543/postgres?sslmode=require
```

Use the **Supabase Transaction Pooler** endpoint (IPv4, port 6543).
Also URL-encode password special characters like `? / + & @ :`.

## 2) Deploy backend to Render (recommended)

This repo includes a ready-to-use Render Blueprint at [render.yaml](render.yaml), configured for `rootDir: backend`.

1. Push this repo to GitHub.
2. In Render, **New → Blueprint** and point it at this repo. Render reads `render.yaml` and proposes the `macquiz-backend` web service on the **Free** plan.
3. Before the first deploy, edit `region` in `render.yaml` (or in the Render dashboard) to the Render region closest to your Supabase project's region - this is Lever 2 from `instruction.txt`: cross-region round-trips cost 100ms+ on every one of the dashboard's sequential queries.
4. Fill in the environment variables Render prompts for (the ones marked `sync: false` in `render.yaml` are not stored in the blueprint and must be entered by you):

```env
DATABASE_URL=postgresql+psycopg://USER:ENCODED_PASSWORD@aws-0-REGION.pooler.supabase.com:6543/postgres?sslmode=require
CORS_ORIGINS=https://your-frontend-domain.vercel.app,http://localhost:5173
ADMIN_EMAIL=admin@macquiz.com
ADMIN_PASSWORD=change-this-password
GEMINI_API_KEY=your-gemini-api-key
```

`SECRET_KEY` is auto-generated by Render (`generateValue: true` in the blueprint) - you don't need to set it.

5. Deploy.
6. Run the one-time database bootstrap (creates tables and seeds the admin user). The app does **not** do this automatically on boot - a fresh deploy or a free-tier spin-up after idling must not pay for schema/admin DB round-trips before serving a request. Run it once, from your machine, pointed at the production `DATABASE_URL`:

```bash
cd backend
DATABASE_URL="postgresql+psycopg://USER:ENCODED_PASSWORD@aws-0-REGION.pooler.supabase.com:6543/postgres?sslmode=require" \
ADMIN_EMAIL="admin@macquiz.com" \
ADMIN_PASSWORD="change-this-password" \
python -m app.bootstrap
```

Re-running it later is safe (it's idempotent) - use it again after adding new model columns.

7. Open the Render backend URL and verify:
   - `/health` reports `"database": "connected"`
   - `/docs` loads
   - login endpoint works

Render's free web services spin down after 15 minutes of no traffic and take a cold restart on the next request - this only replays the FastAPI process boot (no DB writes, per Lever 3), not the one-time bootstrap step above.

## 2b) Alternative: keep the backend on Vercel too

If you'd rather not add a second host, the backend also has [backend/vercel.json](backend/vercel.json) and works fully on Vercel. The steps are the same as section 2, except:
- Set **Root Directory** to `backend` in a Vercel project instead of using the Render Blueprint.
- Add `"regions": ["<region matching your Supabase project>"]` to `backend/vercel.json` (Lever 2) - Vercel has no `region` field to fill in during setup like Render's dashboard does, so this must go directly in the file.
- Every environment variable listed in step 4 above is set the same way, in Vercel's Project Settings → Environment Variables, plus `ALGORITHM=HS256`, `ACCESS_TOKEN_EXPIRE_MINUTES=30`, `CORS_ORIGIN_REGEX=^https://.*\.vercel\.app$`, `CORS_ALLOW_CREDENTIALS=true`, and a manually-chosen `SECRET_KEY` (Render generates this for you; Vercel does not).
- Accept that a serverless backend still cold-starts under bursty traffic even with these fixes applied - this path trades away Lever 1's warm-process win for one less host to manage.

## 3) Deploy frontend to Vercel

Your frontend is already configured with [frontend/vercel.json](frontend/vercel.json).

1. In Vercel, create a project from this repo (a separate project from the backend, even if you chose section 2b's all-Vercel path).
2. Set **Root Directory** to `frontend`.
3. Add environment variable, pointing at whichever backend host you used (Render from section 2, or Vercel from section 2b):

```env
VITE_API_BASE_URL=https://your-backend-domain.onrender.com
```

4. Deploy.

## 4) Update CORS after frontend domain is final

After frontend deploy completes, copy the final frontend URL and update backend `CORS_ORIGINS` to include it.

Example:

```env
CORS_ORIGINS=https://macquiz-frontend.vercel.app,http://localhost:5173
```

Redeploy backend after updating env values.

## 5) First-login checklist

- Login with admin credentials.
- Create one teacher and one student.
- Create a test quiz and submit one attempt.
- Confirm data persists after redeploy.

## 6) If you prefer MySQL

Your backend also supports MySQL (`pymysql` already included). Use this format:

```env
DATABASE_URL=mysql+pymysql://USER:PASSWORD@HOST:3306/DB_NAME
```

But for easiest free setup today, Postgres (Supabase) is typically simpler.
